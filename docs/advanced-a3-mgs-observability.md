# Advanced-A3: MGS, evidence sufficiency and execution visibility

## Architecture and routing

A3 extends the existing A2 selector with `MGS_PATH`. Authentication, access scope, deterministic preflight, A1 exact verified lookup and bounded approved CAG retain their authority. Every output still enters existing governance/HITL. No approval or execution authority is inferred from path selection or evidence coverage.

MGS is selected deterministically for bounded document-only requests such as `Compare multiple SOPs for P-204A`, `Summarize several documents for P-204A`, or `Compare SOP-P204-001 and SOP-P204-002`. The grammar is intentionally conservative: operational qualifiers, safety, P&ID, live sensors and maintenance/operational synthesis retain the existing specialist LangGraph path. Normal single-document knowledge requests retain Hybrid RAG. A1 and CAG exact hits run before MGS. System-1's typed enum accepts MGS but the same document-only deterministic eligibility gate must permit it; the model cannot create eligibility. Currently eligible requests are already handled deterministically, so a planner recommendation adds no privileged shortcut.

A3 adds no parallel retriever or database. The existing knowledge node invokes `retrieve_documents` with `top_k=18` for MGS, retaining access filtering, relevance/identifier-miss checks, hybrid ranking, citations and graph deadlines. Raw evidence remains the state's evidence, including on failure.

## Hierarchical synthesis and provenance

The map stage groups retrieved evidence into at most six groups, each containing at most four evidence records and 12,000 serialized characters. Oversize evidence is rejected, not silently truncated. Each local intermediate generation selects up to eight short verbatim quotations, at most 1,000 characters each, using the existing citation shape.

Code checks every intermediate ID and exact locator against its group and every quoted claim against the original source text. A quotation not present in that source is rejected. Document/version IDs, revision, source hash, locators and other provenance are copied by code from original evidence, never generated by the model. Intermediate summaries are non-authoritative untrusted data; they never enter Qdrant, the verified registry or the evidence list as new sources.

The reduce stage receives bounded extract summaries (at most 24,000 serialized characters), the legitimate user question and existing grounding instructions. Final citations are checked against original evidence using existing citation and authorization-language enforcement. Source state is rechecked before and after final generation. Citation identity is deterministically validated; semantic entailment of every final claim still requires human review. Local generation uses the configured application model, not a new model or hosted inference.

Both source documents and intermediate extracts appear only as untrusted user-message JSON, never as system instructions or tool definitions. There are no new tools, write functions or external calls. Injection resistance retains the existing prompt and output-validation boundaries; no claim of complete semantic injection detection is made.

OCR evidence is not promoted through MGS. The knowledge node retains its existing S3/as-drawn handling and reports a fallback. Confidence, unverified/ambiguous status and original source identity remain intact. OCR does not prove isolation, topology, valve position, permit status or readiness.

## Source checks and deterministic sufficiency

Sufficiency is measured evidence coverage, **not model confidence, factual correctness, current plant readiness or action authorization**.

Required categories are derived by explicit query patterns: sensor/vibration/temperature/pressure; maintenance/history; P&ID/drawing/OCR; SOP; incident; and manual/document/procedure. Static `What is the documented ...` questions do not require current sensor data merely because they mention a measured quantity. Queries without a category default to document evidence.

Present categories come from evidence kinds and authoritative document/structured-record types. Maintenance CSV evidence is distinguished from sensor rows through the existing database resolver. A multi-document request needs at least two document identities.

Non-OCR documents reuse A1 source resolution and exact evidence comparison, including scope, current revision, Qdrant metadata and local source hash. P&ID regions reuse existing artifact/source verification after checking current database lifecycle/scope. Structured rows and sensor windows reuse evidence-integrity source resolution. Empty sensor provenance fails closed. OCR chunk snapshots without current region verification are conservatively marked unavailable. Missing, revoked, stale, inaccessible or unverifiable sources cannot increase coverage.

| State | Deterministic rule |
| --- | --- |
| SUFFICIENT | Required categories and document count present, sources valid, citations available/valid, no recorded tool failure. |
| PARTIAL | Some usable evidence exists, but a noncritical category, citation, source-validity or tool-success check is missing/failing. |
| INSUFFICIENT | No usable evidence, a required sensor/P&ID category is absent, or the answering node reports insufficient evidence. |

Citation checking includes original IDs and exact locators. Missing evidence categories and failed checks are returned and added as explicit response warnings. Coverage rules are coarse and conservative, not a semantic completeness judge or a guarantee that the entire corpus was searched. No model probability contributes to sufficiency.

## Fallbacks

- Invalid/stale MGS sources or fewer than two documents: deterministic S5 with missing evidence; raw references retained.
- Intermediate/final synthesis failure: one bounded direct grounded synthesis over the same raw evidence, if still valid and within 24,000 characters. No new retrieval or summary-as-evidence substitution.
- Failed/oversize fallback: explicit S5 with raw evidence retained.
- Retrieval/graph runtime failure before synthesis: existing Agentic fallback; failures still surface through the existing API error handling if that path also fails.
- OCR encountered: existing knowledge/OCR response, marked as fallback.

The P-204 combined sensor/maintenance/SOP/P&ID advisory continues through its existing specialist and governance flow. A3 adds metadata, not a competing demonstration pipeline.

## Execution metadata and persistence

`QueryResponse.execution` is an optional additive field; old records and preflight-only responses may omit it. It records path, selection source/reason, fallback, verified knowledge identity or pack/version, document/source/evidence counts, MGS group count, sufficiency/missing categories, actual gateway model names/stages/calls, token usage when supplied, and measured latencies.

Counters are request-local ContextVars reset even after errors. Gateway calls include failed calls and schema-repair calls; transport retries inside a runtime are not separately visible. Token totals are unknown (`null`) if any counted call lacks usage. Embedding/reranker inference is outside the generation-call count. Retrieval latency measures registered read-only evidence tools, including structured-data calculations. Total latency covers query execution through metadata assembly, before final governance/database serialization; it is not browser/network latency.

Only compact stage labels, counts and timings are stored. No prompts, model output, intermediate text or chain-of-thought is stored by this instrumentation. Existing run-step JSON stores execution metadata without a new migration. Governed runs persist metadata in their existing transaction; replay reads the original execution snapshot, while governance state is still recomputed by the existing ledger. Existing tracing settings govern optional informational persistence. Execution metadata is observational, not part of the signed advisory's authority and not a substitute for the audit chain.

## Frontend

The existing Workspace result view adds a compact accessible panel for Verified/CAG/Hybrid RAG/MGS/Agentic path, evidence state, source count, model, latency and fallback. It displays missing categories and explicitly states that evidence coverage is not permission to operate equipment. It handles absent metadata without inventing results and exposes no new reasoning trace. The existing approval/evidence layout remains intact.

## Limitations

MGS handles bounded document synthesis, not unlimited recursive corpus summarization or operational multi-agent replacement. It uses extractive intermediate summaries; omitted relevant excerpts and final semantic errors remain possible. Source checks span PostgreSQL/Qdrant/files without a distributed snapshot lock. Strict checks can yield conservative false negatives. No live-model performance claim, KV-cache claim, model download, benchmark change, validation/blind run, or Advanced-B work is included.
